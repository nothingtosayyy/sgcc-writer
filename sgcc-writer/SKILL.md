# 国网材料写作助手（国网信通中心/大数据中心体例）

本技能基于单位公文写作惯例（方案、汇报、规范、报告）整理的写作套路，示例均已脱敏或虚构。目标：承担单位公文初稿工作——引导补料 → 按体例生成 → 直接交付成品文件。

**范围**：仅 WORD 类文档（方案／书面汇报含总结变体／标准规范／调研报告）。PPT、讲话稿不在本技能范围：要 PPT 时说明另用 PPT 技能；要讲话稿时说明暂不支持，可用方案或汇报改写成讲话提纲，但不承诺讲话稿体例。

> **免责声明**：本技能中的示例、演示、数字、单位名称、文号、人名、引文等均为体例演示，已脱敏或虚构处理，不来自真实文档，不涉及真实业务数据，不作为事实依据。正式材料中的事实须由用户提供并核实。

## 适用判断（自动触发，无需用户点名）

出现以下任一情形即视为国网材料，直接使用本技能：

- 文档标题、正文或页眉页脚出现“国网、国家电网、省电力公司、国网信通中心、大数据中心、供电公司”等单位名称；
- 文体为国网常见公文（工作方案、书面汇报、总结、标准规范、调研/研究报告），且使用“一、（一）1.（1）”编号链和本单位称谓口径；
- 用户对上述材料提出润色、顺句、重写章节、按批注修改、压缩扩写、统一口径等改稿要求。

判断存疑时按“疑似国网材料”处理，进入本技能后在第一步向用户确认，不因文体名称不明确而放弃使用。

## 路径判定（先选路径，再执行）

| 场景 | 判定信号 | 走哪条路 |
|---|---|---|
| 从 0 到 1 | 没有现成 WORD 底稿，用户说“写/起草/做一个” | 起草路径（五步工作流） |
| 改这份 | 有现成 WORD 底稿，用户说“改/润色/顺句/按批注/压缩/扩写/统一口径” | 改稿路径 |
| 参照重写 | 有现成底稿，但用户要“照这个写一份新的”（新文种、新年度、新结构） | 起草路径；原稿只作素材，不输出变更对照 |

判定只看两件事：**有没有现成底稿**、**用户要改它还是另写一份**，不看文件名。
中途用户补充新附件或改变要求时，以最新指令重新判路径。

## 改稿模式（现有材料修改）

**进入条件**：用户提供国网现有 WORD 材料，提出润色、顺句、重写章节、按批注修改、压缩扩写、统一口径等要求。改稿不执行“总工作流”的引导补料，直接进入定点编辑。

用户没有点名段落、也没有批注时，先问改哪里，不擅自全文重写。

**做法**：

1. **先定范围**：只改用户点名或批注点到的段落、章节；未点名的内容不动，不顺手重写全文。
2. **先读批注与修订**：逐条列出“编号—意见—落点”，确认本次范围；范围外的批注原样保留，不删除、不代答。
3. **沿用原体例**：字体字号、编号链、图表题注、行距缩进、批注锚点、修订痕迹一律沿用原稿；不整体重排、不套新模板。
4. **定点编辑**：另存新版本文件后按段落定位修改；涉及口径、数字、专名的改动，先核对来源再落笔。默认以修订模式输出（`w:ins` / `w:del`）；用户明确要干净稿时，另出接受修订后的版本。
5. **变更对照**：交付时附“原→新”对照（位置、原文、改后、依据），只列改动项，未改项不列。
6. **改稿自检**：按第五步 A（共用硬伤）+ B2（改稿体例）+ C（共用交付）执行。

**边界**：从零起草仍走五步工作流；改稿只补必要事实，不做通用六问。

**改稿红线**（细则见 [reference-revision.md](reference-revision.md)）：

- 以用户最新附件为基线，不沿用上一轮底稿；
- 含 `w:ins` 的段落不整段重写，按 ins-aware 文本定位后再改；
- 替换或删除段落后重挂批注锚点，交付前核对批注条数；
- 文件被占用时另存新版本，不覆盖、不删锁文件。

## 内容与规则分界（贯穿全流程）

本技能只沉淀**可复用的规则**，不沉淀**一次性的内容**。

| 规则（写入本技能） | 内容（由用户或当期文件提供） |
|---|---|
| 体裁骨架、章节功能、编号链 | 具体章节标题中的业务对象 |
| 句式骨架（A/B/X/Y 占位） | 业务专名、数字口诀的具体词 |
| 口吻、尺度、副词分级 | 指标数值、比例、单位量 |
| 称谓规则、命名规则、自检 | 文号、人名职务、引文原文、具体年度／单位／项目 |

判据：**一条示例换一个主题还能用吗？** 不能，就是内容，必须占位化。

- **占位符**：`〔 〕` = 模板结构位，成品前必须替换完毕；`【 】` = 用户未提供的事实，允许保留但须列清单。
- **语感示例**：需要参考历史写法时，读 `examples/语感示例.md`。它只校准句式、节奏、口吻，其中任何内容都不得复用；默认不读。
- **禁止**：把参考文件或 examples 中的专名、提法、数字、文号、引文直接写入新材料。

## 文件版本与归档（所有路径通用）

1. **先备份，再改**：已有成品后再修改，先复制当前稿到同目录 `历史版本/`，不在原文件上直接改；新稿另存。
2. **改稿命名**：沿用原文件名，追加 `-YYYYMMDD-vN`，如 `产品介绍文档-20260101-v1.docx`。原文件已有版本号则递增：文字修改递增次版本（v3→v3.1），结构调整递增主版本（v3→v4）；原文件无版本号则首次改稿 v1，后续 v1.1 / v2。
3. **起草命名**：仍按 `【YYYY.MM.DD】主题+文种_Vn.n`。
4. **默认修订模式**：改稿默认输出带修订痕迹的 docx（`w:ins` / `w:del`）；用户要干净稿时另出接受修订版，不覆盖修订版。
5. **当场归档**：每次工作结束，把被替换的目标文档旧稿（含用户提供的基线稿）移入同目录 `历史版本/`，当前目录只保留最新稿；只归档本次目标文档的旧版本，不动同目录其它文件。
6. 用户指定归档位置、命名规则或明确要求保留多份时，以用户为准。

## 第二步：引导补料（本技能的灵魂）

**先问后写。** 用 AskUserQuestion 分批提问（每批≤4个问题，问完即写，不无限追问）。用户没答的项用占位符【 】标注，绝不编造事实性内容（数据、人名、文号、日期）。

### 通用六问（所有文体必问或必确认）

1. **主题与事由**：材料讲什么工作？（用户通常已给）
2. **对象与场合**：给谁看/听？（本单位领导／上级公司部门／平级单位／行业会议／培训学员）→ 直接决定口吻
3. **时间坐标**：什么时间用？（决定目标年份、时间节点写法）
4. **篇幅**：给字数档位（2千/5千/万字），或按章节点位说明
5. **依据**：有没有上级文件文号、领导指示原话、会议要求？（方案与落实型材料的导语必需）
6. **素材**：用户手头有哪些数据、做法、进展可写入？（成效数字让用户给，缺失就留【 】）

### 分文体追问（在通用六问之后，详见各参考文件开头的"提问清单"节）

- **方案类**：量化目标（到X年底，XX达到X%）？任务按什么维度切（要素/专业/板块）？谁牵头谁配合？关键时间节点？
- **汇报类**：核心成效数字（累计/覆盖/提升X%）？存在的问题（用于"面对/针对"引子）？下一步3-4条？
- **规范类**：适用范围？强制条款用"应"、推荐用"宜"的尺度？是否走公文印发（需要文号/主送/版记）？
- **报告类**：调研过程数据（去了几家单位/多少人/发现多少问题）？对标对象（外部大厂/系统内同业）？建议要不要带"（时间节点；责任单位）"？

## 第三步：按模板生成

读对应参考文件，严格套用其中的：**目录骨架、编号体系、句式模板、量化句型、修辞套路、口吻规则**。共性文风（所有文体通用）见 [reference-style.md](reference-style.md)，生成任何材料前必读。

参考文件只写规则与占位骨架，不承载可复用的具体内容。需要校准语感时再读 `examples/语感示例.md`，且不得复用其中任何内容（来源登记规则见第四步）。

**长文检查点**：预计超过 5000 字或超过 5 章时，先出章节大纲（标题＋每章要点）给用户确认，再生成全文；用户明确要求直接出全文的除外。

## 第四步：成稿交付

- **生成**：仅 WORD 类（方案／书面汇报／规范／报告），直接生成 .docx 成品文件。生成前调用 `docx` 技能获取 Word 制作规范；中文字体、标题层级、"一、（一）1.（1）"编号按参考文件执行。
- **技能分工**：结构、编号、句式、口吻以本技能为准；页面设置、字体字号、样式实现以 `docx` 技能为准。两者冲突时按此分工处理，不混用。
- **内容来源清单**（生成时同步维护，不写入正文；默认在交付回复中给出，需留档时存 `产物/artifacts/`）：三列 `类别 | 内容 | 来源`。类别覆盖：数字、年份、文号、人名职务、引文、专名、提法、单位／场景。来源只填三种——用户原话（摘原句）、用户提供的文件（文件名＋位置）、【未提供】。正文每一项都必须能在清单中找到，找不到的改为【 】。参考文件与 examples 中的具体内容一律不得直接使用。
- **文件命名**：`【YYYY.MM.DD】主题名称+文种_Vn.n`。日期为交付日期，统一 YYYY.MM.DD（四位年两位月两位日）；版本号统一大写 `V主.次`——初稿 V1.0，文字微调 V1.1、V1.2，结构调整或换版 V2.0；定稿保留版本号，可在文种后加"（终版）"；不再使用 V0.x。培训类加前缀"培训材料｜"；有场合名时场合前置（如"〔场合名〕-〔主题〕"）；正式场合封面日期用汉字数字（如"二〇二六年十月"）。
- **保存位置**（按优先级）：
  1. 用户指定了路径／目录 → 保存在该位置（不存在则创建），不再额外套子目录。
  2. 未指定 → 保存在当前工作目录根目录。
  3. 过程产物与交付物分离：只有最终 docx 留在交付位置；中间产物（大纲、提取内容、内容来源清单草稿）→ `产物/artifacts/`；临时文件／日志／下载 → `产物/tmp/<YYYYMMDD-任务名>/`；生成脚本 → `产物/scripts/`；收尾在 `产物/INDEX.md` 登记，只移不删。本次没有过程文件时不强行建目录。
  4. 交付回复：给出成品绝对路径、字数、未决占位符数量、内容来源清单。不使用 "outputs" 目录或任何文件"present"操作。

## 第五步：交稿自检（A 共用硬伤 → B 路径专属 → C 共用交付）

A 级逐项核对，任一项不过即返工。**起草走 A+B1+C；改稿走 A+B2+C**，两条路径共用一套清单，不再维护第二套。

### A 共用硬伤（两条路径都过，一票否决）

- **A1 数字一致**：同一指标全文一个值/口径/单位；分项之和＝合计、占比×基数＝分项、增长率可复算；附件表与正文同源；每个数字能在《内容来源清单》找到出处，找不到已改【 】；未搬用参考文件或 examples 的示例数字。
- **A2 时间一致**：年份/节点与用户时间坐标一致，无示例年份残留；里程碑先后不矛盾；文件名日期、正文日期、封面年月三者一致。
- **A3 主体与称谓一致**：首次"国家电网有限公司（以下简称'公司'）"后统一"公司"；"国网信通中心（大数据中心）"括号连写；部门、单位、职务与用户提供一致，未被误改。
- **A4 引文可溯源**：领导讲话、政策文件、外部报告：原文＋出处＋日期齐全；不把转述写成引号直引。
- **A5 无虚构、无残留**：无编造数据/文号/人名/日期；无 TODO/待补充/待确认/审稿批注；未出现参考文件或 examples 的具体专名、提法、文号、引文；【 】已列清单，〔 〕已替换完毕。
- **A6 对外口吻**（仅对外材料）：无"请领导审议/请支持/要求/务必/压实"等内部指令口吻；成绩留余地（初步建成/试点应用/约X%）。

### B1 起草体例（仅起草/参照重写）

- **B1-1 编号链**：一、→（一）→1.→（1）→一是二是，无跳级；任务N/问题N跨章连续。
- **B1-2 文体边界**：方案有"特制定本方案"；汇报无"工作目标"章与任务分工表；总结必须有"存在的问题"和"下一年安排"。
- **B1-3 关键句式**：目标章≥3个量化指标并以"支撑X，为公司Y筑牢Z"收尾；思路章数字口诀首次括注展开；保障条目对仗双句、末条落"落地见效"。
- **B1-4 问题表述**："仍/尚未/有待/面对…挑战"，无"缺陷/失误"定性；"短板"仅对外材料可用且须紧跟解法。
- **B1-5 标题与落款**：标题动宾结构、长标题断行；内部材料无落款。

### B2 改稿体例（仅改稿）

- **B2-1 基线清楚**：交付说明写出"基于哪个文件、哪一版"；以最新附件为基线，不沿用上一轮底稿。
- **B2-2 范围与批注覆盖**：附"批注覆盖表"（编号—意见—处理结果—未处理原因）；范围外批注原样保留，未点名内容未动。
- **B2-3 修订保护**：含 `w:ins` 的段落未整段重写；用户已插入文字未被覆盖；新建 run 无 `w:rPrChange`。
- **B2-4 批注锚点**：批注总条数一致；每条有可定位锚点；锚点未挂错章节；未代答、未合并、未改作者。
- **B2-5 图表与脚注**：图号/表号连续；删除图表后引用与空壳同步清理；图随题注、表头跨页重复、脚注正常。
- **B2-6 目检**：导出 PDF 逐页看分页、跨页表格和图片位置。
- **B2-7 变更对照**：附"原→新"变更表（位置、原文、改后、依据），只列改动项。
- **B2-8 修订模式**：默认带 `w:ins` / `w:del`；如另出干净稿，未覆盖修订版。

### C 共用交付（两条路径都过）

- **C1 版本与命名**：起草按 `【YYYY.MM.DD】主题+文种_Vn.n`；改稿按原名 + `-YYYYMMDD-vN`，原文件有版本则递增，无版本从 v1 起。
- **C2 备份与归档**：改前备份到同目录 `历史版本/`；交付后旧稿（含基线稿）归档，当前目录只留最新稿；只归档本次目标文档，不动同目录其它文件。
- **C3 保存与回复**：保存位置符合第四步优先级；只有成品在交付位置，过程文件已归入 `产物/`；回复含绝对路径、字数、占位符数量；起草附内容来源清单，改稿附基线与变更对照（B2-1、B2-7）。

**可机器核对的项**：A5、B1-1、C1 交付前用检索核对——搜 `TODO|待补充|待确认`、查编号跳号、核对文件名与正文年月。

## 共性铁律速览（详见 reference-style.md）

1. **章/段帽段公式**（WORD 每章、每节开头）：`时间背景 + 围绕/聚焦XX + 组织/利用XX + 建成/实现/完成XX（量化）+ 支撑/服务XX`
2. **核心动词十件套**：构建、打造、建成、夯实、贯通、强化、深化、支撑、赋能、落地
3. **标志句式**："以X为抓手/引领/基石"排比；"坚持X、突出X"；"从'X'向'Y'转变"；"可见可管可控"；"一是二是三是四是"
4. **数字提法只学形式，不内置内容**：NX诀、"N要素／N机制／N位一体"等结构可直接套用；具体提法（几个一批、X+Y+Z、业务专名、口径数字）一律由用户或最新官方文件提供，本技能不预设、不得从示例中取用
5. **时间节点句式**："X月底前，完成……"（方案）；"X月，完成……"（年度安排）
6. **保障措施三条公式**：每条 = 对仗双句标题（加强组织领导，强化工作落实）+ 定位句 + 举措句 + 落效句，末条落在"落地见效"
