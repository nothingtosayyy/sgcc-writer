# 标准规范（WORD）写作模板

> 依据规范类写作惯例整理。规范类四亚型体例完全不同，**必须先判型再套模板**。

> **使用约定**：本文件只写规则与占位骨架；`〔 〕`为结构占位，`【 】`为用户未提供的事实。需要语感时读 `examples/语感示例.md`，其中内容不得复用。
>
> **免责声明**：本文示例均为体例演示，已脱敏或虚构，不涉及真实文档与真实数据。

## 0. 提问清单（生成前必问）

1. 亚型判断（给选项）：GB企标体（正式企业标准）／公文通知体（管理办法/应用要求，需印发）／接口规范体／操作手册体（作业指导书/标注指南）
2. 适用范围：本文件规定了……、适用于……？
3. 条款尺度：哪些是硬性要求（应/严禁），哪些是推荐（宜）、允许（可）？
4. 公文印发：需要文号、主送单位吗？（发文部门、年份、序号）
5. 术语定义：需要定义哪些新术语（中文+英文）？
6. 附录：样例表/清单/常见问题？
7. 是否已有可引用的上级标准（GB/DL/T、Q/GDW）？

## 1. GB企标体（Q/GDW正式企业标准）

### 完整骨架
```
封面：ICS分类号占位 + "Q/GDW XXXXX—XXXX"编号（+代替标准）+ 标准名（草案标注）
      + 英文名对照 + 底部"〔发布日期〕发布 〔实施日期〕实施 / 〔发布单位〕 发布"
目　次（TOC，附录写法"附　录　A"中间空两格）
前言（固定六段，见下）
1 范围（"本文件规定了……"+"本文件适用于……"两段式，可加分类划段）
2 规范性引用文件（固定导语+标准号+书名号名称列表）
3 术语和定义（导语"下列术语和定义适用于本文件。"+每条"术语 中文+英文 → 定义句"）
4 缩略语（"〔缩写〕：〔中文全称〕（〔英文全称〕）"式）
5 总则/架构章（愿景与原则 → 架构图"图1"）
6～N 分章技术要求（"应"句要求，多级1.1/1.1.1编号）
附录A（资料性附录）样例表/清单
★关键词／★与法律法规政策的关系／★与国标行标企标国际标准的关系／★与知识产权的关系（申报说明页）
```

### 前言六段（固定结构）
1. "为规范……，确保……，统一……，提升……，制定本文件。"
2. （可选）"本文件使用重新起草法参考ISO/IEC导则第2部分：2004……一致性程度为非等效。"
3. "本文件由〔提出部门〕提出并解释。"
4. "本文件由〔归口部门〕归口。"
5. "本文件起草单位：〔单位1〕、〔单位2〕。本文件主要起草人：〔姓名1〕、〔姓名2〕。"
6. "本文件首次发布。本文件在执行过程中的意见或建议反馈至〔归口部门〕。"

### 措辞体系（GB标准句式铁律）
- "应"=强制："〔对象〕应符合以下要求：……"
- "宜"=推荐："宜按'〔命名规则〕'等格式命名。"
- "可"=允许；"不应/不得/严禁"=禁止
- 引出列项两种固定句式："××应包括以下内容：""××要求如下："
- 编号"1、1.1、1.1.1"（最深四层），章标题不带"第X章"

### 通用目录树（功能骨架，具体章节由标准主题决定）
```
1 范围 2 规范性引用文件 3 术语和定义 4 缩略语
5 基本要求（5.1 〔分类原则〕 5.2 〔格式要求〕 5.3 〔规则〕）
6 技术要求（6.1 〔内容要求〕 6.2 〔质量指标〕（〔指标1/指标2/…〕，各项≥〔X%〕）6.3 〔质检机制〕）
7 执行要求（7.1 〔准备〕 7.2 〔实施〕 7.3 〔检查〕）
附录A～〔N〕（样例、参考指南、验证方法）
```

## 2. 公文通知体（管理办法/应用要求，红头文件）

### 完整骨架
```
〔发文机关〕部门文件（红头）
〔部门代字〕〔年份〕〔序号〕号
〔发文部门〕关于印发XXX（试行）的通知（发文机关+事由+文种）
〔主送单位〕：（主送）
[印发缘由段四件套] "为统筹有序推进……，加快构建……，着力提升……，服务〔行业/公司〕
高质量发展，〔牵头部门〕会同相关部门组织有关单位，制定《XXX（试行）》，现予以印发，请遵照执行。"
正文："一、总体架构（（一）应用步骤（二）应用方式（三）应用架构[图1]）
二、XX技术要求（按要素分（一）～（八），每要素内"N.应用原则/N.构建方式/N.服务方式"三段式）
三、工作要求（"严格落实规范/持续迭代完善/保障数据安全"三句加粗导语式）
适用范围说明
附件：XX关键技术要求（N条，"要素|关键技术要求"两列表，逐条1.～N.编号）
落款：〔发文部门〕 / 〔YYYY年M月D日〕
密级附注："（此件不公开发布，发至收文单位本部。未经公司许可，严禁以任何方式对外传播和发布……违者追究法律责任。）"
版记：〔办公室〕 | 〔YYYY年M月D日〕印发
```

红线句式叠加（结构示例）："严禁搭建〔非统推平台〕""不得直接调用〔特定服务〕""原则上，应基于〔公司统推模型〕构建应用场景，严禁在生产环境独立建设和应用……其他模型""涉及国家秘密、工作秘密……的数据，严禁纳入〔采集范围〕"。

## 3. 接口规范体（技术文档）

每个接口一章，章内**固定七小节**：
```
N. 接口名称
  N.1 数据格式（"请求使用json方式传输，返回的数据采用json方式进行传输"）
  N.2 传输协议（"使用http方式传输"）
  N.3 请求URL（POST http://[IP:PORT|域名]/api/v2/...）
  N.4 请求参数（Headers表+Body表）
  N.5 响应（成功响应：状态码+JSON+字段说明表；错误响应+错误码表）
  N.6 示例请求（Curl命令）
  N.7 应用系统依赖（"需要开通源系统到XX平台的防火墙。"）
```
表头固定：参数表"参数中文名|参数名|类型|示例值|描述|是否必传"；响应表"字段名|类型|描述"；错误码表"错误码|描述"（400请求参数缺失或错误/401认证失败/500服务器内部错误）。
开头：产品名+"XX接口规范"+年月，无公文壳。

## 4. 操作手册体（作业指导书/标注规范）

- 封面三行式：标题+英文副题+"内部资料，请妥善保管"+编制单位+日期（无文号无前言申报页）
- 结构：前言 → 1.目的与范围 → 2.等级划分及依据 → 3.总要求 → 4.考核评估标准 → 5.质检标准 → 主体条目库
- **主体为条目卡片**（每个标签/检查项一张卡片）：
```
缺陷描述：〔对象〕〔部位〕出现〔缺陷现象〕
标签名称：〔一级〕-〔二级〕-〔三级〕-〔四级〕（四级路径命名）
标注要求：在〔载体〕中清晰界定……判断〔缺陷〕是否超过〔阈值〕……
[正例图/案例图]：〔对象〕-〔部位〕-〔缺陷〕-案例1
```
- 质检点配"案例N"表格："错误类型→处理方式→截图"
- 前置科普式论述说明"为什么"（内部规范特有）："〔领域〕的底层逻辑，是……"
- **规范越靠近一线操作，案例化程度越高**（大量"如下图所示"正误对照）

## 5. 量化阈值写法（只给句型，具体数值由标准原文确定）

- 分级写法："〔A级〕：〔标准〕／〔B级〕：〔标准〕／〔C级〕：〔标准〕"
- 缺陷三级："〔紧急〕（需立即处理）／〔重大〕（尽快处理）／〔一般〕（可结合计划处理）"
- 抽检与合格线："随机抽取〔X%〕作为基本质检量""从剩余样本中随机抽取〔Y%〕二次审核""合格率需达到〔Z%〕以上""各项指标应达到≥〔X%〕的合格线""一致率≥〔X%〕认定为'高度一致'；〔Y%〕～〔X%〕'基本一致'；<〔Y%〕需重新标注"
- 考核挂钩："完成量达到〔X%〕及以上视为合格""连续〔N〕周低于〔X%〕的，暂停下发新任务"
- 公式化定义："〔指标〕=〔正确数量〕/〔总数量〕×100%"
