# 改稿参考（现有材料修改）

用于“改稿模式”。只写改稿规则，不承载具体内容。配合 `SKILL.md` 的“改稿模式”使用。

## 1. 基线与版本

- 以用户**最新附件**为唯一基线；开改前三查：文件名与日期、批注条数、修订标记数量（`w:ins` / `w:del`）。
- 不沿用上一轮底稿，不自动合稿；用户说“以该附件为准”时，旧稿只作对照。
- 原稿不动，另存新版本；命名按 `SKILL.md`「文件版本与归档」执行：沿用原文件名并追加 `-YYYYMMDD-vN`（如 `产品介绍文档-20260101-v1.docx`）。原文件已有版本号则递增：文字修改递增次版本（v3→v3.1），结构调整递增主版本（v3→v4）；原文件无版本号则首次改稿 v1，后续 v1.1 / v2。交付时写明基线文件名与版本。
- 改稿默认以修订模式输出（`w:ins` / `w:del`）；用户明确要干净稿时，另出接受修订后的版本，不覆盖修订版。
- 改前把当前稿复制到同目录 `历史版本/`；交付后旧稿归档（含用户提供的基线稿），当前目录只保留最新稿；只归档本次目标文档的旧版本，不动同目录其它文件。
- 正文日期、封面日期、文件名日期三者不一致时，先向用户确认，不自行改。

## 2. 用户修订保护

- **取文**：`python-docx` 的 `paragraph.text` 不包含 `w:ins` 内的文字。含修订的段落必须用 ins-aware 取文（遍历 `w:r` 与 `w:ins` 下的 `w:t`），否则会出现“段落明明是空的，其实有内容”。
- **改文**：含 `w:ins` 的段落不做整段替换，只改用户点名或批注点到的 run；不得覆盖用户已插入的文字。
- **新建内容**：标签加粗与正文常规拆成两个 run；段落格式从正文段复制，不从标题段复制（避免继承楷体、大纲级别、`keepNext`）。
- **清痕迹**：新建 run/单元格不要携带 `w:rPrChange`，否则 WPS 会按“格式修订”显示蓝下划线。
- **回读**：保存前按 ins-aware 文本核对目标段落，确认用户原文与新增内容都在。

## 3. 批注锚点保活

- 改前导出批注清单：`id`、作者、锚点段落文本、是否存在 `commentRangeStart` / `commentRangeEnd`。
- 替换或删除段落后，原锚点会随之丢失。替换前先保存 `commentRangeStart`、`commentRangeEnd`、`commentReference` 元素，替换后在新段落重挂。
- 只有姓名、没有意见正文的批注（如“田戈”），按其所处章节推断归属，保留并在交付说明中单列，不擅自删除。
- 范围外的批注原样保留；不代答、不合并、不改作者。
- 交付前核对：批注总条数一致；每条都有可定位锚点；锚点没有挂到错误章节。

## 4. 文件占用与另存

- 出现 `PermissionError`、`~$` 锁文件或写入被拒绝：不覆盖、不删锁、不杀进程；另存新版本文件并说明原因。
- 只清理自己产生的 `.tmp`，不动用户打开中的临时文件。
- 交付路径：用户指定目录 > 工作目录根目录；过程文件按工作区规则进 `产物/`。

## 5. 改稿自检（交付前逐项过）

1. 基线清楚：交付说明写出“基于哪个文件、哪一版”。
2. 范围清楚：附“批注覆盖表”（编号—意见—处理结果—未处理原因）。
3. 数字与专名：未被误改；与表格、附件口径一致。
4. 批注：条数一致、锚点有效、范围外未动。
5. 编号：图号、表号连续；删除图表后同步清理引用和空壳。
6. 图表与脚注：图随题注、表头跨页重复、脚注正常显示。
7. 目检：导出 PDF 逐页看分页、跨页表格和图片位置。
8. 对照：附“原→新”变更表，只列改动项。
9. 版本与归档：新稿命名/版本正确；旧稿已归入 `历史版本/`；当前目录只留最新稿。
10. 修订模式：默认带 `w:ins` / `w:del`；如另出干净稿，未覆盖修订版。
